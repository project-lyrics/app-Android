# 목표

- 이번 세션으로 발생한 staged 변경사항만 커밋

# 사전 실행 사항

- `git fetch`를 이용해 다른 작업자의 변경 사항이 있는지 먼저 확인
  - 다른 사용자의 변경 사항이 이미 있다면 커밋 작업을 중단하고 사용자에게 안내
- staged 변경이 있는지 먼저 확인
  - staged 변경이 없으면 커밋 작업을 중단하고 사용자에게 안내

# 워크플로우

1. staged 변경만 확인한다
   - unstaged 변경이나 untracked 파일을 자동으로 포함하지 않는다
2. 최근 5개 커밋 메시지를 확인해 저장소 스타일을 참고한다
3. `./agent/rules/git-commit-rules.md` 기준으로 커밋 메시지를 작성한다
   - 형식은 `type: Subject`
   - 커밋 메시지는 영문으로 작성한다
   - 제목은 명령형으로 쓰고, 50자 이내를 우선하며 72자를 넘기지 않는다
   - 제목 끝에는 마침표를 붙이지 않는다
   - 단순 변경은 제목만 사용하고, 맥락이 필요하거나 제목 50자 안에 충분히 설명이 안 되면 본문을 추가한다
4. 사용자가 커밋 메시지를 확인하거나 확정하기 전에는 `git commit`을 실행하지 않는다
5. 커밋 후에는 상태를 확인한다

# 제약 사항

- 이번 변경사항이 아닌 다른 변경사항을 커밋에 포함하면 안 됨
- staged 변경만 커밋 대상에 포함해야 함
- `./agent/rules/git-commit-rules.md`의 커밋 메시지 규칙을 우선 적용
